## 1. 验证目标

验证 Framework D1 候选基线能否在同一参考工程中：

1. 将已确认的探索钓点设计语言扩展到账号和“我”；
2. 先完成发布钓点产品范围、页面规格和平台适配，再制作高保真；
3. 用同一可运行移动原型串联首页、登录、资料、账号和发布；
4. 以真实浏览器、双主题和同组视觉比较证明候选结果，而不是只提供静态图片。

## 3. 真实反馈

- 同一产品内更新既有页面视觉时，必须保留“既有批准稿”和“新候选稿”两个状态，不能用候选视觉静默覆盖已批准事实；
- 设计系统复用不能只检查颜色，必须同时复核图像策略、信息层级、面板、间距、主操作和平台行为；
- 新业务高保真必须同时覆盖入口条件、主任务、预览、提交中和结果状态；
- 对带审核流程的内容发布，“提交成功”必须明确为“进入审核”，不能表达为已经公开；
- 视觉来源和新实现放入同一比较输入，比孤立截图更容易发现风格漂移。

## 4. 结论边界

本次参考采用达到 `conditional_pass`，等待维护者确认。它为 D1 候选基线提供了更完整的单项目证据，但暂不提升任何体验与设计工程资产成熟度：

- 不代表账号新视觉已批准；
- 不代表发布钓点产品范围已批准；
- 不代表 iOS、服务端、OpenAPI、数据库或真机实现通过；
- 不代表 D2 已退出；
- Framework 稳定版本继续为 `v0.1.10`。
