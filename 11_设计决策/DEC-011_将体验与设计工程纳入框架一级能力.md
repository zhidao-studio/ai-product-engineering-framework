# DEC-011：将体验与设计工程纳入框架一级能力

- 状态：已接受
- 日期：2026-07-25
- 决策人：项目负责人
- 关联文档：`13_体验与设计工程/README.md`

## 1. 背景

Framework 已定义用户体验设计、高保真预览与确认、视觉 Agent 和模板计划，但缺少一套可直接指导页面设计、平台适配、Design Tokens、实现映射和验收的权威规范。

YouYu 探索钓点高保真迭代暴露出：

- 参考图片、HTML 高保真和真实客户端之间缺少映射；
- 页面缺少统一设计系统与页面规格；
- iOS 原生组件、桌面组件和 H5 组件的适用边界不清；
- “高保真已批准”和“真实客户端已验收”的结论容易混淆；
- 设计经验只停留在单次页面修改，无法成为 Framework 可复用资产。

## 2. 备选方案

1. 继续只在项目仓库维护页面说明和高保真；
2. 把 UI/UX 规则并入 Harness 或模板目录；
3. 建立“体验与设计工程”一级专业能力，跨阶段提供规范、模板和检查关卡。

## 3. 决定

采用方案 3。

新增 `13_体验与设计工程/`，覆盖：

- 体验与设计工程总则；
- 跨平台交互与组件适配；
- 设计系统与 Design Tokens；
- 页面设计规范；
- 高保真交付与实现映射；
- 视觉与体验验收。

同时在模板和 Harness 中增加候选执行资产。

## 4. 模型边界

本决定：

- 不新增第十一个产品生命周期阶段；
- 不新增第六类 AI 工程基础设施；
- 不改变三平面模型；
- 不把体验责任交给 AI；
- 不要求不同平台像素完全一致。

体验与设计工程是横跨用户体验设计、高保真、工程规格、执行、验证和模拟用户验收的专业能力。

## 5. 跨平台原则

采用：

> 同一产品目标和体验语义保持一致，各客户端优先使用对应平台的原生交互、系统组件和可访问性能力。

iOS、Android、桌面、桌面 Web 和 H5 可以共享业务、品牌和语义 Token，但必须分别说明导航、控件、手势、窗口、权限、反馈和响应式行为。

## 6. 影响

- Roadmap 增加里程碑 D；
- Framework 项目 Context 进入 D1；
- 用户可见任务的高保真必须声明目标平台；
- 页面设计不再只交付图片，需要页面规格和平台适配矩阵；
- YouYu 探索钓点将作为首个参考采用任务；
- 新规范和模板保持 `candidate`，真实采用前不升级稳定版本或成熟度。

## 7. 替代条件

只有真实跨平台项目证明该模块与现有三平面冲突，或规范无法支持不同客户端时，才可通过新的设计决策替代。单个项目可以记录合理例外，但不得静默改变 Framework 权威规则。
