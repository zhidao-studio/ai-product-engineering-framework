# 体验与设计一致性检查规范

> 本规范控制用户可见变更从产品定义、高保真到客户端实现和用户验收的边界。

当前成熟度：`candidate`

## 1. 适用范围

- 新页面；
- 主导航、信息架构或核心流程变化；
- 主要视觉方向、组件组合和内容层级变化；
- 正常、加载、空、错误、权限、离线等状态变化；
- 新增或调整客户端平台；
- 实现与批准高保真不一致。

## 2. 执行前检查

- [ ] 产品范围和业务规则已批准；
- [ ] 页面目标、用户流程和信息架构明确；
- [ ] 目标平台已声明；
- [ ] 跨平台适配矩阵已完成；
- [ ] 设计系统版本和 Token 来源明确；
- [ ] 页面设计规范覆盖状态和交互；
- [ ] 对应平台高保真可浏览；
- [ ] 人工批准记录存在；
- [ ] 任务 Context 引用上述版本和允许修改范围。

任一关键项缺失时，用户可见实现默认 `blocked`。不适用必须有理由和批准人。

## 3. 实现中检查

- 平台实现使用批准的语义和平台组件；
- 不用代码中的临时视觉反向覆盖设计事实；
- Design Tokens 与平台代码映射可追溯；
- 新增视觉值、组件或交互差异有来源；
- 平台限制引起设计变化时暂停并退回设计确认；
- 不修改任务范围外页面来追求“整体协调”。

## 4. 实现后检查

- [ ] 构建或静态检查通过；
- [ ] 在目标设备或浏览器运行；
- [ ] 核心路径和返回成立；
- [ ] 页面适用状态已触发；
- [ ] 明暗、尺寸、字体和可访问性按计划检查；
- [ ] 高保真和实现截图在同一数据与状态下比较；
- [ ] 差异已修复或有人工批准例外；
- [ ] 用户验收范围和未验证项已记录；
- [ ] 产品、设计、代码和 Context 已完成必要回写。

## 5. 结论边界

```text
高保真批准 ≠ 实现通过
构建通过 ≠ 视觉通过
视觉接近 ≠ 交互正确
模拟器通过 ≠ 真机通过
单平台通过 ≠ 其他平台通过
核心路径通过 ≠ 全状态或发布通过
```

## 6. 失败退回

| 发现 | 退回 |
|---|---|
| 用户目标或范围错误 | 产品定义 |
| 导航、流程或信息层级错误 | 用户体验设计 |
| 视觉、状态或组件组合错误 | 高保真原型预览与确认 |
| 平台组件或实现映射不可行 | 工程规格与平台适配 |
| 代码偏离批准设计 | 受控任务执行 |
| 证据不足 | 质量验证或模拟用户验收 |
