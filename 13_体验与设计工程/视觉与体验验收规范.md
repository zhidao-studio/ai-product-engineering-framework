# 视觉与体验验收规范

## 1. 四层证据

| 层 | 证明什么 | 不能证明什么 |
|---|---|---|
| 设计完整性 | 页面、状态、平台和 Token 已定义 | 客户端已实现 |
| 静态实现检查 | 组件、资源、文案和结构可审查 | 运行布局正确 |
| 运行视觉与交互 | 目标设备/浏览器中的布局、操作和状态成立 | 用户接受、生产稳定 |
| 模拟用户验收 | 指定用户路径被人类接受 | 全量设备和长期运行稳定 |

## 2. 最小运行矩阵

按任务适用范围选择：

| 平台 | 最小检查 |
|---|---|
| iOS | 目标真机或模拟器、小屏、大字体、明暗模式、键盘、返回、VoiceOver专项 |
| iPadOS | 横竖屏、分栏、窗口变化、键盘 |
| macOS / Windows | 最小/常用/大窗口、鼠标、键盘、快捷键、右键、系统主题 |
| 桌面 Web | 主流浏览器、常用宽度、键盘、浏览器返回、缩放 |
| H5 | iOS Safari、Android Chrome 或项目目标浏览器、软键盘、安全区、返回和刷新 |
| Android | 目标设备/模拟器、系统返回、字体缩放、明暗模式、TalkBack专项 |

未执行的组合必须标为未验证，不能写成通过。

## 3. 验收检查

- 页面目标和主要操作一眼可识别；
- 导航和返回符合平台习惯；
- 设计系统版本和页面实现一致；
- 正常、加载、空、错误、离线和权限状态按适用范围存在；
- 文案、单位、时间、隐私和危险操作准确；
- 触摸目标、键盘、焦点和辅助功能可用；
- 滚动、固定区、Sheet、Dialog 和键盘不遮挡内容；
- 明暗模式和对比度可读；
- 动效不阻碍任务，减少动态效果得到尊重；
- 高保真与实现差异已处理或有批准例外；
- 人类批准人实际操作核心路径。

## 4. 结论

| 结论 | 条件 |
|---|---|
| `passed` | 计划范围全部完成，无阻塞问题 |
| `conditional_pass` | 核心范围可继续，但存在明确未验证项或非阻塞问题 |
| `blocked` | 核心路径、关键状态、平台适配或批准缺失 |
| `failed` | 已执行范围出现不可接受结果 |

构建成功、截图存在、高保真批准都不能单独得出 `passed`。
