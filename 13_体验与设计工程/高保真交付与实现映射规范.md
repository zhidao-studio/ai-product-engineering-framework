# 高保真交付与实现映射规范

## 1. 高保真的职责

高保真负责：

- 展示批准后的视觉层级；
- 表达关键交互和状态；
- 让人能在实现前确认体验；
- 为工程规格和实现提供可引用依据。

高保真不负责：

- 代替产品范围和业务规则；
- 自动成为所有平台的共同实现；
- 证明真实客户端已经通过；
- 用漂亮图片掩盖缺失状态。

## 2. 交付包

每个高保真版本至少包含：

```text
版本与状态
目标平台和尺寸
主路径页面
关键状态页面
交互说明
Design Tokens版本
平台适配矩阵
页面设计规范
可浏览入口
批准记录
已知限制
```

## 3. HTML 原型的适用边界

HTML/CSS/JavaScript 适合：

- 快速浏览信息架构和视觉层级；
- 模拟流程、状态和数据；
- 通过链接让产品负责人评审；
- 为 AI 提供结构化页面参考。

HTML 原型不等于 iOS、Android 或桌面原生实现。它不得作为以下结论的单一证据：

- 原生导航、返回和手势正确；
- 键盘、Safe Area 和系统权限正确；
- Dynamic Type、VoiceOver 或 TalkBack 正确；
- 原生地图、相机、分享、通知和多窗口正确；
- 真机性能和触感反馈正确。

## 4. 实现映射表

实现前必须建立映射：

| 设计对象 | 语义 | 设计系统来源 | 平台实现 | 验证 |
|---|---|---|---|---|
| 主导航 | 一级目的地切换 | `navigation.primary` | iOS `TabView` | 真机切换与状态保持 |
| 天气入口 | 当前区域天气摘要 | `weather.summary-card` | SwiftUI Button + Sheet | 点击、加载、失败 |
| 地图钓点卡 | 切换当前钓点 | `spot.map-carousel` | Map + 横向滚动卡片 | 左右滑动与地图联动 |

没有映射的视觉元素不得由开发人员随意解释。

## 5. 视觉比较

实现后的比较至少固定：

- 高保真版本和批准提交；
- 客户端代码提交；
- 设备、系统、尺寸和主题；
- 页面数据和状态；
- 高保真截图与实现截图；
- 差异、影响、修复或批准例外。

视觉相似只是验收的一部分，系统交互、可访问性和用户路径仍需真实运行。

## 6. 修改规则

```text
设计本身错误 → 退回体验或高保真并重新批准
实现偏离设计 → 修实现
平台限制 → 更新平台适配和高保真后再批准
业务规则变化 → 退回产品定义
```

禁止在代码 Review 中默认批准视觉变化。
