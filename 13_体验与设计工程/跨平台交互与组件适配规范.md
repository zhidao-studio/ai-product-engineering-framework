# 跨平台交互与组件适配规范

## 1. 总原则

> 统一体验语义，优先平台原生习惯，保留品牌识别，不追求跨平台像素复制。

平台适配顺序：

```text
用户目标与业务规则
→ 语义组件和状态
→ 目标平台能力与习惯
→ 平台组件和交互
→ 品牌视觉适配
→ 目标设备验收
```

## 2. 平台差异矩阵

| 维度 | iOS / iPadOS | macOS / Windows 桌面 | 桌面 Web | H5 / 移动 Web | Android |
|---|---|---|---|---|---|
| 主要输入 | 触摸、手势、键盘、辅助技术 | 鼠标、键盘、触控板、快捷键 | 鼠标、键盘、浏览器能力 | 触摸、软键盘、浏览器能力 | 触摸、系统返回、键盘 |
| 主导航 | Tab Bar、NavigationStack、Sidebar | Sidebar、Toolbar、菜单、窗口 | 顶栏、侧栏、URL 路由 | 精简顶栏、必要时底部导航 | NavigationBar、NavigationRail、Drawer |
| 次级呈现 | Sheet、Popover、全屏覆盖 | Panel、Popover、Dialog、新窗口 | Dialog、Drawer、独立 URL | Bottom Sheet、全页、浏览器返回 | Bottom Sheet、Dialog、Activity/Route |
| 返回 | 导航栏返回、边缘滑动 | 窗口、层级导航、Esc、快捷键 | 浏览器返回、面包屑、URL | 浏览器返回、页面返回 | 系统返回、顶部返回 |
| 上下文操作 | Swipe、Context Menu、长按 | 右键、菜单、Toolbar、快捷键 | Hover、右键受限、菜单 | 长按谨慎使用、更多菜单 | 长按、Context Menu、Swipe |
| 布局 | Safe Area、Dynamic Type、尺寸级别 | 可缩放窗口、多栏、密度 | 响应式、宽屏、多栏 | 窄屏、浏览器栏、安全区 | Adaptive Layout、系统栏 |
| 反馈 | Alert、Banner、Haptic、Progress | Dialog、通知、状态栏、Progress | Toast、Inline、Dialog、Progress | Inline、Toast、Sheet、Progress | Snackbar、Dialog、Haptic、Progress |

## 3. 语义组件映射

语义组件描述“它解决什么问题”，平台组件描述“该平台如何呈现”。

| 语义组件 | iOS 示例 | 桌面示例 | H5 示例 |
|---|---|---|---|
| `primary_navigation` | 原生 Tab Bar 或 Sidebar | Sidebar / Toolbar / 菜单 | 精简顶栏；仅在核心并列目的地稳定时使用底部导航 |
| `secondary_navigation` | NavigationStack | 内容层级、面包屑、分栏 | 浏览器路由和返回 |
| `single_choice` | Picker、Menu、Sheet | ComboBox、Radio、Popover | Select、Radio、Bottom Sheet |
| `destructive_confirmation` | 系统 Alert / Confirmation Dialog | Dialog | Dialog 或全页确认 |
| `context_actions` | Swipe Actions、Context Menu | 右键菜单、Toolbar | 更多菜单，避免依赖 Hover |
| `detail_inspection` | Push、Sheet、全屏媒体 | 详情面板、新窗口 | 独立页面或全屏媒体 |
| `loading_feedback` | ProgressView、骨架 | Progress、状态区 | 骨架、行内进度 |

上述只是选择范围，不是固定答案。页面规范必须记录最终选择及理由。

## 4. iOS / iPadOS

- 优先 SwiftUI 或 UIKit 的系统导航、控件、Sheet、Alert、Context Menu 和手势；
- 遵守 Safe Area、Dynamic Type、VoiceOver、明暗模式和触控目标；
- 不用自绘控件破坏系统返回、键盘、焦点和辅助功能；
- iPad 需要评估 Sidebar、Split View、多窗口和横屏，而不是放大 iPhone；
- SF Symbols 可作为系统语义图标，品牌图标另行管理；
- 关键页面必须在目标 iPhone 尺寸验证，小屏和大字体不可仅靠静态图推断。

## 5. macOS / Windows 桌面

- 以窗口、Sidebar、Toolbar、菜单、快捷键、右键和 Hover 为基础能力；
- 支持窗口缩放、最小尺寸、宽屏信息密度和多任务；
- 高频操作应提供键盘路径，不能只有触摸式大按钮；
- macOS 和 Windows 可以共享业务与品牌，但系统菜单、窗口行为、控件密度和快捷键需分别适配；
- 不把手机底部 Tab Bar 放大后当作桌面导航。

## 6. 桌面 Web

- URL、浏览器前进后退、刷新、深链接和焦点顺序是产品行为的一部分；
- 响应式布局不是简单缩放，应定义断点后的信息层级和导航变化；
- Hover 只能增强，不能成为唯一入口；
- 表单、错误、加载和空状态必须支持键盘和屏幕阅读器；
- SEO、打印、下载和多标签页只在业务适用时纳入。

## 7. H5 / 移动 Web

- H5 是运行在浏览器中的触摸界面，不等同于原生 App；
- 必须考虑浏览器地址栏、返回、刷新、软键盘、Safe Area 和分享打开方式；
- 相机、定位、文件、通知等能力必须按浏览器权限和失败路径设计；
- 不假设原生 Sheet、原生 Tab Bar、Keychain 或系统级后台能力必然存在；
- 页面要在常见移动浏览器与实际 viewport 验证；
- PWA 能力属于明确选择，不能默认假设。

## 8. Android

- 遵循系统返回、系统栏、权限、NavigationBar/NavigationRail 和自适应布局；
- 不把 iOS 的导航、手势和图标语义直接复制到 Android；
- 评估不同尺寸、分屏、字体缩放和 TalkBack；
- 品牌层可以一致，系统行为和组件优先采用 Android 平台习惯。

## 9. 平台选择记录

每个页面至少记录：

```yaml
target_platforms:
  - ios
  - h5
shared_experience_intent: 用户可以在当前位置发现并比较附近钓点
platform_adaptations:
  ios:
    navigation: 原生Tab与NavigationStack
    map_detail: 可拖动Sheet
  h5:
    navigation: 浏览器路由与返回
    map_detail: 底部浮层或独立详情页
non_shared_behavior:
  - iOS使用系统地图与原生导航应用选择
  - H5使用浏览器地图链接与权限提示
```

未声明目标平台的高保真不能自动成为其他平台的实现依据。
