# 体验与设计工程

> 本模块把“用户体验设计”和“高保真原型预览与确认”转化为可执行、可检查、可映射到不同客户端的工程能力。

当前成熟度：`candidate`

## 1. 定位

体验与设计工程不是新的生命周期阶段，也不是第六类 AI 工程基础设施。它是贯穿以下阶段的横向专业能力：

```mermaid
flowchart LR
    P["产品定义"] --> U["用户体验设计"]
    U --> H["高保真原型预览与确认"]
    H --> E["工程规格设计"]
    E --> I["受控任务执行"]
    I --> V["质量与安全验证"]
    V --> A["模拟用户验收"]
    A -.反馈.-> U
```

它负责将“用户想完成什么”逐步转化为：

1. 平台无关的体验意图；
2. 平台适配后的交互与组件；
3. 可浏览、可确认的高保真；
4. 可供开发实现的页面规格；
5. 可比较、可验收的视觉与交互证据。

## 2. 核心规则

```text
同一产品目标
→ 统一用户流程与语义
→ 统一品牌与 Design Tokens
→ 按平台采用原生交互和组件
→ 形成平台高保真
→ 映射到真实客户端实现
→ 在目标设备和浏览器验收
```

跨平台一致不等于像素完全相同：

- 必须一致：业务含义、用户目标、核心信息、状态语义、品牌识别和安全承诺；
- 可以不同：导航、控件、手势、窗口、布局密度、反馈方式和系统能力；
- 不得不同：业务规则、权限含义、错误事实和验收结论。

## 5. 当前边界

- 本模块不提供一套可直接复制到所有产品的固定视觉风格；
- 不要求所有客户端像素一致；
- 不允许用 HTML 高保真代替 iOS、Android 或桌面端的原生交互判断；
- 不允许仅凭图片或静态页面宣布真实客户端体验通过；
- 候选规范已在 YouYu 完成探索钓点、账号与“我”视觉更新和发布钓点的统一高保真参考采用；维护者确认前仍不能写成完整参考验证通过。

## 6. 外部参考

Framework 借鉴成熟设计系统的组织方式，但不复制其品牌或组件：

- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)：Apple 平台的基础、模式、组件和输入规范；
- [Microsoft Fluent 2 Design Principles](https://fluent2.microsoft.design/design-principles)：强调体验应适应设备和平台，并优先复用原生组件与模式；
- [IBM Carbon Design System](https://carbondesignsystem.com/all-about-carbon/what-is-carbon/)：将设计语言、指南、工具、组件和代码实现组成完整系统；
- [Atlassian Design System](https://atlassian.design/get-started/about-atlassian-design-system)：通过 foundations、tokens、components 和文档集中保存设计决定；
- [Ant Design 设计模式](https://ant.design/docs/spec/overview-cn/)：将一般概念、组件、业务模块、页面模板和功能示例分层组织。

这些来源用于验证 Framework 的结构方向。具体产品仍必须根据用户、业务、品牌和目标平台建立自己的设计系统。
